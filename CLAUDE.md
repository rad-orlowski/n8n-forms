# n8n-forms

A self-contained React form console that POSTs to n8n webhooks. The build output is a
**single, portable `forms.html`** that runs from `file://` with no server.

## Key facts
- **Package manager:** `bun` — use `bun` everywhere, not npm/yarn/pnpm
- **No SSR, no server.** The app is a static SPA routed by URL hash (`#/`, `#/<slug>`)
- **Secrets are inlined at build time** — webhook URLs come from `.env` (gitignored) and
  are baked into `forms.html`. Anyone with the file can read them. Never commit `.env`
- `forms.html` is also gitignored (build artifact); `.env.example` is the tracked template

## Commands
```
bun dev              # dev server (http://localhost:5173)
bun run build        # Vite build → dist/
./bundle-artifact.sh # full pipeline: bun build → patch → inline → forms.html
```

## File://  + CORS
When opened via `file://`, the page origin is `null`. Every n8n Webhook node must have
**Allowed Origins = `*`**. A CORS block surfaces as a network/timeout error (status 0).

## How to add a form
1. Create `forms/<slug>.form.ts` — `export default defineForm({...})`
2. Set `webhook: import.meta.env.VITE_WEBHOOK_<YOUR_KEY>` and add the key to `.env` / `.env.example`

The app auto-discovers every `*.form.ts` in `forms/` — no registration step needed.

See `forms/CLAUDE.md` for the full schema reference, and `src/components/fields/CLAUDE.md` to add a custom field type.

## How to add a field type
1. Build a React component accepting `{ field, def }: FieldComponentProps`
2. Add one entry to `FIELD_REGISTRY` in `src/components/fields/index.ts`
3. Use the new `type` string in any `*.form.ts`

See `src/components/fields/CLAUDE.md` for the full step-by-step and contract.

## Architecture
- `src/lib/schema.ts` — `FieldDef`, `FormSchema`, `ResponseConfig`, `ResponseField`, `defineForm()`, `buildZodSchema()`, `defaultValues()`
- `src/lib/submit.ts` — `postToWebhook()` using `ky`; POST retry intentionally disabled (double-trigger risk)
- `src/components/FormShell.tsx` — single template: RHF + zod, field registry dispatch, submit + error/success UI; `ResponsePanel` renders `FormSchema.response` fields from the webhook's JSON reply using `es-toolkit/compat` `get()`; the reply may be a bare object `{...}` or array-wrapped `[{...}]` — `resolveResponseValue` normalizes both, so response keys are written object-style (e.g. `body.message`) and a legacy `0.` prefix is still tolerated
- `src/components/fields/` — field components + `FIELD_REGISTRY`; `rich-text-field.tsx` debounces TipTap `onUpdate` via `es-toolkit` `debounce` (~250 ms trailing, flush on blur, cancel on unmount)
- `forms/` — one `*.form.ts` per form (top-level, auto-discovered); `ping.form.ts` is the smoke-test (message field + webhook echo response config); `src/forms/index.ts` is the shim that loads them all via `import.meta.glob`
- `src/components/tiptap-*/` — **vendored**, generated by `npx @tiptap/cli add simple-editor`; prefer regenerating over hand-editing
- `src/index.css` — "industrial control panel" theme (dark charcoal/amber); imports `src/styles/_tiptap-theme-overrides.scss` for TipTap palette; animation utilities: `animate-rise`, `animate-error-in`, `animate-panel-in`, `animate-field-in`, `animate-shake`; full `prefers-reduced-motion` guard
- `es-toolkit` — used for `debounce` (TipTap field) and `get` via `es-toolkit/compat` (response dot-path resolution)
